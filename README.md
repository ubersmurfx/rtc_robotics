# RTC Robotics

Система дистанционного управления роботами ЦНИИ РТК (ровер и учебные платформы). Проект состоит из двух частей: **пульт** (ноутбук оператора) и **робот** (Raspberry Pi на борту).

Репозиторий: [github.com/ubersmurfx/rtc_robotics](https://github.com/ubersmurfx/rtc_robotics)

## Архитектура

```
┌─────────────────────┐         TCP :65432          ┌─────────────────────┐
│       ПУЛЬТ         │ ◄────────────────────────► │        РОБОТ        │
│  Ubuntu 22.04       │                            │  Raspberry Pi       │
│                     │         UDP RTP :8554        │                     │
│  onpult.py          │ ◄────────────────────────── │  rpi_sender.py      │
│  rpi_reciever.py    │      (видеопоток H.264)      │  onboard.py         │
└─────────────────────┘                            └─────────────────────┘
         ▲                                                    ▲
         │                                                    │
    Клавиатура оператора                          Моторы, сервоприводы,
                                                  камера, дисплей, фара
```

**Пульт** принимает команды с клавиатуры и отправляет их роботу по TCP. **Робот** принимает команды, управляет моторами, манипулятором, камерой и фарой, а также передаёт видео с камеры на пульт по UDP.

Оба устройства должны находиться в одной локальной сети (подключены к одному Wi-Fi роутеру).

## Структура проекта

| Каталог / файл | Назначение |
|---|---|
| `config/pult_params.yaml` | IP-адрес робота и параметры соединения для пульта |
| `config/robot_params.yaml` | Параметры робота: порты, раскладка клавиш, сервоприводы, видеопоток |
| `pult_ws/onpult.py` | Основной скрипт управления с пульта (клавиатура → TCP) |
| `pult_ws/keypad_setup.py` | Привязка клавиш к командам |
| `robot_ws/onboard.py` | Точка входа на роботе — запуск TCP-сервера |
| `robot_ws/handler.py` | Обработка команд, управление подсистемами робота |
| `robot_ws/h39.py` | Драйвер моторов (BTS7960) и фары |
| `robot_ws/servo.py` | Управление сервоприводами через I2C (PCA9685) |
| `robot_ws/event.py` | События и логика сервоприводов |
| `robot_ws/disp/` | OLED-дисплей (SSD1306): статус и логотип ЦНИИ РТК |
| `video_utility/rpi_sender.py` | Отправка видеопотока с камеры робота |
| `video_utility/rpi_reciever.py` | Приём и отображение видео на пульте |
| `service/` | systemd-сервисы для автозапуска на роботе |
| `installation/` | Скрипты установки зависимостей |

## Требования

### Пульт (оператор)

- Ubuntu 22.04
- Python 3 + виртуальное окружение
- GStreamer (`gstreamer1.0*`, `libgstreamer1.0-0`, `gstreamer1.0-tools`)
- Рекомендуемое ПО: [RealVNC](https://www.realvnc.com/en/), [VS Code](https://code.visualstudio.com)

### Робот (Raspberry Pi)

- Raspberry Pi с камерой
- Python 3 + виртуальное окружение
- GStreamer, `rpicam-vid`
- Зависимости из `requirements.txt` (RPi.GPIO, Adafruit, OpenCV, picamera и др.)

## Установка

### 1. Клонирование репозитория

На **пульте** и **роботе**:

```bash
git clone -b rev_2.0_B https://github.com/ubersmurfx/rtc_robotics.git
cd rtc_robotics
```

### 2. Установка системных пакетов

**На пульте:**

```bash
bash installation/pult_install.sh
bash installation/install_rtc_robotics.sh
```

**На роботе** (дополнительно — настройка камеры):

```bash
bash installation/install_rtc_robotics.sh
bash installation/mod_boot.sh   # включает камеру в /boot/firmware/config.txt
sudo reboot
```

### 3. Виртуальное окружение и Python-зависимости

На обоих устройствах:

```bash
cd ~
python3 -m venv venv_rtc_rover
source ~/venv_rtc_rover/bin/activate

cd rtc_robotics
pip install -r requirements.txt
```

Для удобства активацию окружения можно добавить в `~/.bashrc`:

```bash
echo 'source ~/venv_rtc_rover/bin/activate' >> ~/.bashrc
```

### 4. Автозапуск сервисов на роботе (опционально)

```bash
cd rtc_robotics/service
bash services_setup.sh
```

## Настройка

Перед первым запуском укажите IP-адреса в конфигурационных файлах.

### Пульт — `config/pult_params.yaml`

```yaml
configuration:
  HOST: "192.168.0.36"   # IP-адрес робота в локальной сети
  PORT: 65432
```

### Робот — `config/robot_params.yaml`

```yaml
configuration:
  HOST: "192.168.0.6"           # IP-адрес робота (на котором слушает сервер)
  PORT: 65432
  STREAM_TARGET: "192.168.0.5"  # IP-адрес пульта (куда отправляется видео)
  STREAM_PORT: 8554
```

### Пути к конфигурации в коде

В некоторых файлах пути заданы жёстко — замените `USERNAME` или имя пользователя робота на актуальные:

| Файл | Что заменить |
|---|---|
| `pult_ws/onpult.py` | `/home/USERNAME/rtc_robotics/config/pult_params.yaml` |
| `robot_ws/onboard.py` | `/home/RTC-B-2.0-002/rtc_robotics/config/robot_params.yaml` |
| `robot_ws/handler.py` | то же |
| `robot_ws/disp/display.py` | путь к шрифту `PixelOperator.ttf` |
| `service/*.service` | `User`, `Group`, `WorkingDirectory`, `ExecStart` |

### SSH-доступ к роботу

```bash
ssh <имя_робота>@<ip_адрес>
```

## Использование

> **Важно:** сначала включите робота и дождитесь появления логотипа ЦНИИ РТК на дисплее, затем запускайте скрипты на пульте.

### Шаг 1 — Включить робота

Если настроены systemd-сервисы, ПО запускается автоматически при подключении к сети. Иначе на роботе вручную:

```bash
source ~/venv_rtc_rover/bin/activate
cd ~/rtc_robotics/robot_ws
python3 onboard.py
```

В отдельном терминале на роботе (для видео):

```bash
source ~/venv_rtc_rover/bin/activate
cd ~/rtc_robotics/video_utility
python3 rpi_sender.py
```

### Шаг 2 — Запуск на пульте

Подключите пульт к той же Wi-Fi сети, что и робот.

**Приём видеопотока:**

```bash
source ~/venv_rtc_rover/bin/activate
cd ~/rtc_robotics/video_utility
python3 rpi_reciever.py
```

**Управление роботом:**

```bash
source ~/venv_rtc_rover/bin/activate
cd ~/rtc_robotics/pult_ws
python3 onpult.py
```

## Управление с клавиатуры

### Движение

| Клавиша | Действие |
|---|---|
| `w` | Вперёд |
| `s` | Назад |
| `a` | Танковый поворот налево |
| `d` | Танковый поворот направо |
| `q` | Поворот колёс налево |
| `e` | Поворот колёс направо |
| `r` | Нулевое положение |
| `t` | Колёса ромбом |

### Скорость

| Клавиша | Действие |
|---|---|
| `z` | Замедлиться |
| `x` | Ускориться |

### Камера

| Клавиша | Действие |
|---|---|
| `1` | Опустить камеру |
| `2` | Поднять камеру |

### Манипулятор

| Клавиша | Действие |
|---|---|
| `u` / `h` | 1-е звено (вверх / вниз) |
| `i` / `j` | 2-е звено |
| `o` / `k` | 3-е звено |
| `p` / `l` | 4-е звено |
| `g` / `y` | Схват (открыть / закрыть) |

### Фара

| Клавиша | Действие |
|---|---|
| `v` | Включить |
| `b` | Выключить |

## Автозапуск на роботе

В каталоге `service/` находятся два systemd-сервиса:

| Сервис | Скрипт | Назначение |
|---|---|---|
| `robot_controller.service` | `robot_ws/onboard.py` | TCP-сервер управления |
| `rpi_streamer.service` | `video_utility/rpi_sender.py` | Видеопоток с камеры |

Оба сервиса перезапускаются автоматически при сбое (`Restart=on-failure`). После настройки через `services_setup.sh` робот готов к работе через 10–15 секунд после включения.

Проверка статуса:

```bash
sudo systemctl status robot_controller.service
sudo systemctl status rpi_streamer.service
```

## Особенности и устранение неполадок

| Ситуация | Решение |
|---|---|
| Пульт не подключается к роботу | Убедитесь, что робот включён и на дисплее отображается логотип. Проверьте IP в `pult_params.yaml`. |
| Нет видео | Проверьте `STREAM_TARGET` и `STREAM_PORT` в `robot_params.yaml`. Убедитесь, что GStreamer установлен на обоих устройствах. |
| Робот перезапускается | Это нормальное поведение — сервисы настроены на автоперезапуск при ошибках. |
| `onpult.py` запущен до робота | Соединение не установится. Перезапустите `onpult.py` после готовности робота. |
| Ошибки камеры на Pi | Выполните `installation/mod_boot.sh` и перезагрузите робота. |
